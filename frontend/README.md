# Tabys Consulting — сайт и админка

Корпоративный сайт ТОО «Табыс Consulting» (Алматы): производство оборудования
из нержавеющей стали для пищевой промышленности. Здесь же живёт интерфейс
админки — раздел `/admin`, который работает с API из `../backend`.

Next.js 16.4 (App Router, Turbopack), React 19, Tailwind CSS v4, TypeScript.

## Запуск

```bash
npm install
cp .env.example .env.local
npm run dev     # http://localhost:3000
npm run build   # продакшен-сборка
npm run lint
npx tsc --noEmit
```

Каталог на сайте, админка и форма заявки берут данные из бэкенда на порту
4000 — см. `../backend/README.md`. Без него сайт открывается, но каталог пуст.
Прод-сборка и деплой — в `../README.md`.

## Окружение

| Переменная | Когда читается | Зачем |
| --- | --- | --- |
| `API_URL` | при запросе | базовый URL API вместе с `/api/v1`; серверная, в браузер не попадает |
| `API_ORIGIN` | **при сборке** и при запросе | origin, под которым браузер видит `/uploads`; попадает в `images.remotePatterns` |
| `NEXT_PUBLIC_SITE_URL` | **при сборке** | адрес сайта для canonical, sitemap и JSON-LD; в прод-сборке обязателен |

Образец — `.env.example`. В dev бэкенд на `localhost`, поэтому в
`next.config.ts` для dev включён `images.dangerouslyAllowLocalIP` — иначе
оптимизатор картинок Next 16 отвечает 400 на локальный адрес.

| Путь | Что это |
| --- | --- |
| `src/app/(site)/` | публичные страницы (главная, каталог, линии, услуги, проекты, о компании, контакты, политика) |
| `src/app/(site)/oborudovanie/[category]/[product]/` | страницы категорий и товаров |
| `src/app/admin/` | админка: вход, заявки, каталог, медиа, профиль |

| `src/components/` | `layout/` — шапка и подвал, `ui/` — общие элементы, `admin/` — элементы админки, `home/` `catalog/` `contacts/` `forms/` — блоки страниц |
| `src/lib/api/` | клиент API: `public.ts` — каталог для сайта, остальное — админка (типы, ошибки, cookie-сессия, обновление токена) |
| `src/lib/catalog-urls.ts` | адреса страниц каталога — единственное место, где они собираются |
| `src/lib/admin/` | Server Actions админки и состояние форм |
| `src/lib/content/` | **текстовый контент публичного сайта**: контакты, услуги, проекты, линии, навигация |
| `src/lib/actions/` | Server Action формы заявки |
| `src/assets/images/` | фотографии вёрстки (статический импорт) |

Группа `(site)` на адреса не влияет: страницы как были `/oborudovanie`, так и
остались. Она появилась, чтобы шапка и подвал сайта не оборачивали админку.

Тексты страниц (телефоны, адрес, услуги, проекты) лежат в `src/lib/content/`.
Каталог — нет: его правят в админке.

## Каталог на сайте

Категории, товары и фильтры приходят из `/public/*` бэкенда через
`src/lib/api/public.ts`. Адреса:

| Адрес | Что это |
| --- | --- |
| `/oborudovanie` | оглавление: все категории, фильтры и поиск (на клиенте — категорий дюжина) |
| `/oborudovanie/<категория>` | страница категории: описание, товары, SEO-поля из админки |
| `/oborudovanie/<категория>/<товар>` | страница товара: галерея, характеристики, цена, форма заявки с названием товара |

У обеих страниц свои `<title>`, description, canonical, Open Graph и JSON-LD
(`BreadcrumbList`, у товара — `Product`). Все они попадают в `sitemap.xml`.
Старые адреса `/oborudovanie?cat=<слаг>` уводит 308 в `src/proxy.ts`.

**Кеш.** Ответы бэкенда кешируются (`use cache`, тег `catalog`, `cacheLife("hours")`).
Каждое действие админки с каталогом, фильтрами и медиа вызывает
`updateTag("catalog")`, и сайт показывает правку со следующего запроса.
Кеш — в памяти процесса, поэтому экземпляр фронтенда должен быть **один**:
второй не узнает о сбросе тега.

**Сборка от бэкенда не зависит.** Если бэкенд доступен во время `next build`,
каталог попадает в статику; если нет — эти части рендерятся по первому запросу.
Поэтому всё, что читает каталог, стоит под `<Suspense>`, а страницы категории
и товара объявлены блокирующими (`instant = false`): так несуществующий адрес
отвечает настоящим 404, а не «мягкой» 404 со статусом 200.

## Админка

`/admin`, вход по email и паролю администратора из бэкенда.

| Раздел | Что умеет |
| --- | --- |
| Заявки | список с фильтром по статусу, поиском и постраничностью; карточка: переходы статуса, внутренняя заметка, ответственный, скачивание вложений |
| Категории | список, публикация, удаление, порядок на сайте, форма с фильтрами, картинкой и SEO |
| Товары | фильтр по категории и статусу, форма с характеристиками и ценой, порядок внутри категории |
| Фильтры | значения фасетов: добавить, переименовать, упорядочить, удалить неиспользуемое |
| Медиа | загрузка до 10 МБ, подписи (alt), удаление неиспользуемых |
| Профиль | свои данные и смена пароля |

### Сессия

Два httpOnly-cookie: `tabys_at` (access-токен) и `tabys_rt` (refresh). Токены
не попадают в JS браузера — все запросы к Nest уходят с сервера Next.

`maxAge` access-cookie равен времени жизни токена, поэтому «куки нет» означает
«токен истёк», и `src/proxy.ts` обходится проверкой наличия, без разбора JWT.
Истёкший токен обновляет `/api/admin/session` — Route Handler, потому что
**писать cookie может только он или Server Action**, страница не может.

Обновление токена сделано single-flight (`src/lib/api/refresh.ts`): бэкенд
считает повторное предъявление отозванного refresh-токена утечкой и гасит всё
семейство сессий. Два параллельных обновления одной строкой выбросили бы
администратора отовсюду.

## Особенности этой версии Next.js

В `next.config.ts` включён `cacheComponents`. Из-за этого:

- **нельзя** вызывать `new Date()` (без аргументов), `Date.now()`,
  `Math.random()`, `crypto.randomUUID()` при рендере страницы — сборка упадёт.
  Год в подвале задан константой `COPYRIGHT_YEAR` в `src/lib/content/company.ts`,
  а `renderedAt` в форме заявки ставится в `useEffect`.
  `new Date(строка)` с аргументом безопасен — на нём построен
  `src/lib/admin/format.ts`;
- `useSearchParams` работает только внутри `<Suspense>` (см. `src/app/(site)/oborudovanie/page.tsx`).
  В админке его нет: фильтры — обычные GET-формы, списки читают `searchParams` на сервере;
- route segment configs `dynamic` / `revalidate` / `fetchCache` не поддерживаются.
  Динамичность страницы задаёт само чтение `cookies()`, а разрешает блокирующий
  рендер `export const instant = false` — он стоит на `src/app/admin/layout.tsx`
  и на каждой странице админки;
- после мутации в Server Action нужен `refresh()` из `next/cache`: данные
  админки не кешируются, но клиентский роутер держит готовый RSC-ответ;
- функция с `use cache` не должна бросать: ошибка изнутри неё на пререндере
  валит сборку, даже если её поймать снаружи, а наружу выходит обычным `Error`
  без своего класса. Поэтому `load()` в `src/lib/api/public.ts` возвращает
  `ok` / `missing` / `failed`, а сбой помечает `cacheLife({ revalidate: 0 })` —
  такая запись не хранится.

Middleware в Next 16 называется **proxy** и лежит в `src/proxy.ts`.

Документация под установленную версию лежит в `node_modules/next/dist/docs/`.

## Форма заявки

`src/lib/actions/request.ts` проверяет поля и отправляет заявку в бэкенд
(`POST /public/leads`) вместе с вложением. Заявка появляется в `/admin/leads`.

Успех показывается **только** после ответа 2xx: раньше здесь был `console.info`,
и заявки с сайта молча терялись. Если бэкенд не отвечает или сработал лимит,
форма говорит об этом и предлагает позвонить или написать в WhatsApp.

В форме есть ловушка для ботов (скрытое поле `companyWebsite`) и отметка
времени показа — бэкенд помечает такие заявки спамом, отвечая при этом успехом.

Вложение ограничено 4 МБ. `bodySizeLimit` поднят до 5 МБ, потому что в тело
Server Action входят ещё поля формы и служебные байты multipart. Caddy перед
Next своего лимита на тело не ставит.

### IP посетителя

Заявка уходит с сервера Next, поэтому бэкенд видит его адрес, а не адрес
посетителя. Мы пробрасываем `X-Forwarded-For`, но бэкенд доверяет этому
заголовку, только если у него задан `TRUST_PROXY`. Без этого в `Lead.ip`
попадёт адрес Next, а лимит «20 заявок в час на IP» окажется общим для всех
посетителей сразу.

## Фотографии

Фото вёрстки лежат в `src/assets/images/` и подключаются статическим импортом:

```tsx
import weldingPhoto from "@/assets/images/welding.jpg";

<ImageSlot src={weldingPhoto} alt="Сварка ёмкости" />
```

Списка «какие файлы есть» больше нет: опечатка в имени ломает сборку, а не
превращается молча в плейсхолдер. Размеры и размытая превьюшка берутся из
файла сами. Заменить фото — положить файл с тем же именем; добавить —
положить файл и импортировать там, где он нужен. Плейсхолдер `<ImageSlot>`
рисует, только когда `src` пуст: фото ещё не сняли или его не загрузили
в медиатеку.

Изображения сгенерированы нейросетью как временная замена — их нужно
заменить на реальные фото производства. Фото для насосов, «другого
оборудования» и торцевых уплотнений нет: у этих категорий обложку
загружают в админке, и блок уплотнений на главной берёт её оттуда же.

**Превью ссылки** (WhatsApp, Telegram, соцсети) — `src/assets/og-image.jpg`,
1200×630, подключена в `src/lib/seo.ts`. Страницы категорий и
товаров подставляют свою обложку (через оптимизатор Next, чтобы тяжёлый
оригинал не остался без превью), остальные — эту. Заменить можно любым
JPEG 1200×630 до ~300 КБ: тяжелее WhatsApp показывает ненадёжно.
Заголовки превью страниц — `pageMetadata()` в `src/lib/seo.ts`.

Картинки, загруженные в админку, лежат не здесь, а в `../backend/uploads`
и раздаются бэкендом. Фото категорий и товаров на сайте — именно оттуда.
