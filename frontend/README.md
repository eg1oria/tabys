# Tabys Consulting — сайт и админка

Корпоративный сайт ТОО «Табыс Consulting» (Алматы): производство оборудования
из нержавеющей стали для пищевой промышленности. Здесь же живёт интерфейс
админки — раздел `/admin`, который работает с API из `../backend`.

Next.js 16.4 (App Router, Turbopack), React 19, Tailwind CSS v4, TypeScript.

## Запуск

```bash
npm install
cp .env.example .env.local
npm run dev     # http://localhost:3000
npm run build   # продакшен-сборка
npm run lint
npx tsc --noEmit
```

Публичные страницы работают без бэкенда. Для `/admin` и для отправки заявок
нужен бэкенд на порту 4000 — см. `../backend/README.md`.

## Окружение

Обе переменные **серверные**, без `NEXT_PUBLIC_`: ни адрес API, ни тем более
токены не должны попадать в браузер.

| Переменная | Зачем |
| --- | --- |
| `API_URL` | базовый URL API вместе с `/api/v1` |
| `API_ORIGIN` | origin бэкенда для картинок из `/uploads` |

Образец — `.env.example`.

## Структура

| Путь | Что это |
| --- | --- |
| `src/app/(site)/` | публичные страницы (главная, каталог, линии, услуги, проекты, о компании, контакты, политика) |
| `src/app/admin/` | админка: вход, заявки, каталог, медиа, профиль |
| `src/app/api/admin/` | Route Handlers админки: обновление сессии, загрузка картинок, скачивание вложений |
| `src/proxy.ts` | проверка сессии перед рендером `/admin/*` |
| `src/components/` | `layout/` — шапка и подвал, `ui/` — общие элементы, `admin/` — элементы админки, `home/` `catalog/` `contacts/` `forms/` — блоки страниц |
| `src/lib/api/` | клиент админского API: типы, ошибки, cookie-сессия, обновление токена |
| `src/lib/admin/` | Server Actions админки и состояние форм |
| `src/lib/content/` | **текстовый контент публичного сайта**: контакты, категории, услуги, проекты, линии |
| `src/lib/actions/` | Server Action формы заявки |
| `public/images/` | фотографии |

Группа `(site)` на адреса не влияет: страницы как были `/oborudovanie`, так и
остались. Она появилась, чтобы шапка и подвал сайта не оборачивали админку.

Контент публичных страниц по-прежнему лежит в обычных TypeScript-модулях, без
БД и внешних запросов — поэтому они собираются статически. Чтобы поправить
телефон, адрес или список категорий, правьте файлы в `src/lib/content/`.
Каталог в админке правит **свою** базу — публичные страницы его пока не читают.

## Админка

`/admin`, вход по email и паролю администратора из бэкенда.

| Раздел | Что умеет |
| --- | --- |
| Заявки | список с фильтром по статусу, поиском и постраничностью; карточка: переходы статуса, внутренняя заметка, ответственный, скачивание вложений |
| Категории | список, публикация, удаление, порядок на сайте, форма с фильтрами, картинкой и SEO |
| Товары | фильтр по категории и статусу, форма с характеристиками и ценой, порядок внутри категории |
| Фильтры | значения фасетов: добавить, переименовать, упорядочить, удалить неиспользуемое |
| Медиа | загрузка до 10 МБ, подписи (alt), удаление неиспользуемых |
| Профиль | свои данные и смена пароля |

### Сессия

Два httpOnly-cookie: `tabys_at` (access-токен) и `tabys_rt` (refresh). Токены
не попадают в JS браузера — все запросы к Nest уходят с сервера Next.

`maxAge` access-cookie равен времени жизни токена, поэтому «куки нет» означает
«токен истёк», и `src/proxy.ts` обходится проверкой наличия, без разбора JWT.
Истёкший токен обновляет `/api/admin/session` — Route Handler, потому что
**писать cookie может только он или Server Action**, страница не может.

Обновление токена сделано single-flight (`src/lib/api/refresh.ts`): бэкенд
считает повторное предъявление отозванного refresh-токена утечкой и гасит всё
семейство сессий. Два параллельных обновления одной строкой выбросили бы
администратора отовсюду.

## Особенности этой версии Next.js

В `next.config.ts` включён `cacheComponents`. Из-за этого:

- **нельзя** вызывать `new Date()` (без аргументов), `Date.now()`,
  `Math.random()`, `crypto.randomUUID()` при рендере страницы — сборка упадёт.
  Год в подвале задан константой `COPYRIGHT_YEAR` в `src/lib/content/company.ts`,
  а `renderedAt` в форме заявки ставится в `useEffect`.
  `new Date(строка)` с аргументом безопасен — на нём построен
  `src/lib/admin/format.ts`;
- `useSearchParams` работает только внутри `<Suspense>` (см. `src/app/(site)/oborudovanie/page.tsx`).
  В админке его нет: фильтры — обычные GET-формы, списки читают `searchParams` на сервере;
- route segment configs `dynamic` / `revalidate` / `fetchCache` не поддерживаются.
  Динамичность страницы задаёт само чтение `cookies()`, а разрешает блокирующий
  рендер `export const instant = false` — он стоит на `src/app/admin/layout.tsx`
  и на каждой странице админки;
- после мутации в Server Action нужен `refresh()` из `next/cache`: данные
  админки не кешируются, но клиентский роутер держит готовый RSC-ответ.

Middleware в Next 16 называется **proxy** и лежит в `src/proxy.ts`.

Документация под установленную версию лежит в `node_modules/next/dist/docs/`.

## Форма заявки

`src/lib/actions/request.ts` проверяет поля и отправляет заявку в бэкенд
(`POST /public/leads`) вместе с вложением. Заявка появляется в `/admin/leads`.

Успех показывается **только** после ответа 2xx: раньше здесь был `console.info`,
и заявки с сайта молча терялись. Если бэкенд не отвечает или сработал лимит,
форма говорит об этом и предлагает позвонить или написать в WhatsApp.

В форме есть ловушка для ботов (скрытое поле `companyWebsite`) и отметка
времени показа — бэкенд помечает такие заявки спамом, отвечая при этом успехом.

Вложение ограничено 4 МБ. `bodySizeLimit` поднят до 5 МБ, потому что в тело
Server Action входят ещё поля формы и служебные байты multipart; на Vercel
потолок ~4,5 МБ, и для файлов крупнее нужен свой хостинг или загрузка напрямую
в бэкенд.

### IP посетителя

Заявка уходит с сервера Next, поэтому бэкенд видит его адрес, а не адрес
посетителя. Мы пробрасываем `X-Forwarded-For`, но бэкенд доверяет этому
заголовку, только если у него задан `TRUST_PROXY`. Без этого в `Lead.ip`
попадёт адрес Next, а лимит «20 заявок в час на IP» окажется общим для всех
посетителей сразу.

## Фотографии

Изображения в `public/images/` сгенерированы нейросетью как временная замена —
их нужно заменить на реальные фото производства.

Чтобы подставить настоящее фото: положите файл в `public/images/` с тем же именем.
Если файла нет, компонент `<ImageSlot>` рисует аккуратный плейсхолдер вместо битой
картинки. Список доступных файлов — в `src/lib/images.ts`, туда же добавляются новые.

Ещё не сгенерированы (сейчас показываются плейсхолдером или переиспользуют другое фото):
`seals.jpg` (торцевые уплотнения), `cat-pumps.jpg` (насосы), `cat-other.jpg`,
`facility.jpg` (фасад производства), фото для блока «Решения».

Картинки, загруженные в админку, лежат не здесь, а в `../backend/uploads`
и раздаются бэкендом.
